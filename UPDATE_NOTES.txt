- Loading a texture for a plugin is much faster: the loader now keeps one copy queue and fence and reuses them instead of building and tearing them down for every texture (in game, a 256x256 upload went from about 29 ms to about 0.7 ms, and copying a game icon from about 29 ms to about 0.3 ms)
- The first plugin texture to load no longer causes a short freeze: the loader now sets up its texture copy queue once the game's graphics are ready, instead of on that first load
- Mod windows no longer blink when the game gains or loses focus (for example after Alt-Tab), and the log now records focus changes
- When the game has updated ahead of the mod loader, the game keeps loading while the mod loader's message is up, instead of freezing for up to 3 minutes waiting for your answer, and the message stays on top of the game window
- A fresh install opens a window titled Mod Loader Installed instead of Plugins Updated
- Adapting to a new game version is quieter: the log no longer warns about every field on a build that has no map row of its own and is checked against another build's row. Those differences are now Debug lines, and the game's value is still the one used
- Plugins can now ask for the size of a game struct the game does not describe itself. The loader serves it from the version map's row for your game build, and turns the feature off on a build with no row. Structs the game does describe still use the game's own size. The compatibility report lists every size a plugin asked for
- For plugin authors: PLUGIN_FIELD_ANY_SIZE now also works for a native member. The loader serves the offset and size from the map's row for your game build, so a plugin that only takes the member's address no longer has to know its size
- For plugin authors: plugins can now ask where the game puts a game function's parameters and how big its parameter block is, so a plugin calling a game function keeps working when a game update adds or moves a parameter
- For plugin authors: that also works for a function of a Blueprint class that is not loaded yet (a UI widget, say). The new PLUGIN_FIELD_LATE flag makes the plugin's feature wait, with a note in the log and the compat report instead of a warning, and start once the game loads the class
