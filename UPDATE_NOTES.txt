- The Plugins Updated window is wider on large screens, so its notes no longer wrap into a thin column at 4K, and its title and Close button stay in view when the list is long
- After the mod loader updates itself, the Plugins Updated window lists the loader's release notes once, including the notes of releases you skipped
- Loading a texture for a plugin is much faster: the loader now keeps one copy queue and fence and reuses them instead of building and tearing them down for every texture (in game, a 256x256 upload went from about 29 ms to about 0.7 ms, and copying a game icon from about 29 ms to about 0.3 ms)
- The first plugin texture to load no longer causes a short freeze: the loader now sets up its texture copy queue once the game's graphics are ready, instead of on that first load
- Mod windows no longer blink when the game gains or loses focus, and the log now records focus changes
- When the game has updated ahead of the mod loader, the game keeps loading while the mod loader's message is up, instead of waiting up to 3 minutes for your answer
- A fresh install opens a window titled Mod Loader Installed instead of Plugins Updated
- The log no longer warns about every field on a build that has no map row of its own and is checked against another build's row; those differences are now Debug lines, and the game's value is still the one used
- PLUGIN_FIELD_ANY_SIZE now also works for a native member: the loader serves the offset and size from the map's row for your game build, so a plugin that only takes the member's address no longer has to know its size
- Plugins can now ask for the size of a game struct the game does not describe itself; the loader serves it from the version map's row for your game build, and turns the feature off on a build with no row. Structs the game does describe still use the game's own size, and a map row that disagrees is only logged. The compatibility report also lists every size a plugin asked for, and is now written on any launch where one did
