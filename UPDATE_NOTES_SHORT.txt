- A plugin that names the game build it was made for now loads on that build after a game update changed only some of the game classes the loader checks, instead of showing as incompatible
- The mod loader is now built for game build CL-130045 and still runs on CL-127004. The dedicated server stays on CL-127004
- The dedicated server now supports the version object map: built-in rows for its own game build (CL-127004), the same Game-SDK globals as the client, and its own signed version map file so a newer server game build can be supported without a loader update ([AutoUpdate] Enabled=0 stops that request). On a server build only that file lists, if the loader cannot find everything it needs, the server starts with no plugins and ModLoader.log says why. ModLoader.log also prints one line per build in a fetched file
- When the game does not finish starting within the mod loader's wait on a build the mod loader was not made for, its message now says the game did not finish starting (and to check the game files in Steam) instead of saying the game layout changed. Plugins stay off for that session
- The wait for the game to finish starting is now a true 2 minute limit
- Plugin data now also crosses between a server and a player on different versions of the same plugin, when the plugin says those versions are compatible (an optional GetPluginWireInfo export); it holds for data in both directions. When it cannot, ModLoader.log names the plugin and both versions on each side. A server with an older mod loader still needs identical plugin versions
